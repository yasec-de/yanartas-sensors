
LLM Usage Policy within the Yanartas project
============================================

In this project, we consider limited LLM use acceptable, in accordance with [nlnet's policy on LLM
usage](https://nlnet.nl/foundation/policies/generativeAI/2.0/).

Acceptable use
--------------

We consider the following uses acceptable:

1. Using an LLM to review written content for spelling, grammar and structure to produce feedback for the author. LLM
   output must not end up in the document.
2. Using an LLM to research facts and figures where that research would be too time-consuming if not using an LLM (this
   policy item is necessary to allow us to use Google search).
3. Using an LLM for routine formatting or data processing tasks. In this electronics project, this means for instance
   distilling pinout and package definition parameters from a datasheet, a task that is not only really tedious and
   boring, but also more error-prone if done by hand, with incorrect data leading to a total production failure. Of
   course, these numbers need to be verified by hand, but using an LLM saves copying hundreds of entries from a poorly
   formatted word document.
4. Using an LLM to review code or schematic documents and provide feedback to the user if this use avoids (a) human
   labor or (b) CO2 emissions in proportion to the emissions produced by the use.

Since 1. is very efficient with LLMs, and 2. is rare for this sort of project, we expect the overwhelming majority of
LLM use in this project to happen for 3 and 4. As a baseline for this sort of use, consider the first larger, multi-hour
LLM session used here, which was a production review of several schematics and PCB layout before submitting them for
production. The review used computing resources corresponding to an API usage cost of about 80 USD. Note that this cost
is only a reference number and does not correspond to actual cost incurred since we use a flat rate subscription plan.

LLM Review Carbon Footprint
---------------------------

Based on this API cost figure, we can calculate a very rough, worst-case approximation of the CO2 emissions generated by
this use. You can find the precise calculation with inputs and sources in llm-estimation.py. For the review sessions,
the script calculates a worst-case total of about 1.5 kg of CO2 emissions.

To contextualize this, consider this carbon footprint figure published by Raspberry Pi for one of their recent boards. 
[Raspberry Pi states](https://www.raspberrypi.com/news/16gb-raspberry-pi-5-on-sale-now-at-120/) that the carbon
footprint of the Pi 5 is 6.5 kg per board. The boards we create in this project are a little bit more complex than the
raspberry pi, and a typical prototype run is five circuits board produced with two assembled, shipped from China via air
freight. As a rough estimation, we expect a footprint of 10 - 20 kg CO2 for a single prototype production run of our
boards plus ~10 kg for usually two separate shipments from China, one for the partially assembled boards and one for the
remaining components leading to a total of roughly 30 kg per prototype run.

This means that expending roughly 1.5 kg of emissions on a LLM-automated review can potentially save us roughly 30 kg of
emissions for an additional prototyping run. Now, not every review will uncover blocking issues that would have
precluded a fix through PCB rework and necessitated a full re-run, but at a factor of 1:20 in emissions incurred vs.
potentially saved, the breakeven is at only a 5% chance of a breaking bug in the finished design, which from experience
is much below the actual defect rate, especially for first prototypes. Consequentially, we consider this use of an LLM
for review appropriate.

Procedures for LLM use
----------------------

For spellchecking use or research, we don't keep an itemized account. We do keep one for more heavyweight use in
[llm-logs.toml](./llm-logs.toml). In that file, we list the reason for use, the model used, the API cost corresponding
to the use and the corresponding CO2 emissions. We found the cost figure to be the only consistent usage metric provided
through Anthropic's interfaces for use of the Claude models.
